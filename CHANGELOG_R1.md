# Changes for revision 1 (JORS, October 2026)

This file records, with dates, every change made to the reproduction package in
response to the first-round review. Results reported in the revised manuscript are
regenerated by the modules listed here from the stored forecasts; nothing in the
original forecast files was modified.

## Corrections to existing code (2026-10-27)

- `src/eval/inventory_sim.py`
  - **Lead-time target.** For lead time L > 0 the order-up-to level was the single-day
    quantile for day t, which under-covers the protection interval t…t+L. The target is
    now the q-quantile of the (L+1)-day sum, approximated from the daily quantile grids
    under independence (`--lead-target independent`, Monte Carlo, default) or as the
    comonotone sum of daily quantiles (`--lead-target comonotone`, upper bound). The
    previous behaviour is kept as `--lead-target same-day` for reproduction only.
    The one-day lead-time sensitivity reported in the submitted version is withdrawn.
  - **Terminal inventory.** Stock left at the end of the window was unvalued;
    `--terminal waste` charges it as waste. Both treatments are reported as bounds.
  - The daily order of operations (arrival → review/order → demand, FIFO → holding,
    expiry, ageing), the absence of daily re-forecasting and the two-day burn-in are
    documented in the module docstring and in Appendix D.1.
- `src/experiments/add_empirical_quantiles.py`: `--uncensored-only` restricts the
  validation residuals to days without a stockout hour (output suffix `equ`); the main
  specification is unchanged and uses all validation days.
- `src/experiments/run_finetune_chronos2.py`, `src/experiments/run_lightgbm.py`:
  `--cutoff-date` (and `--min-context-days`) retrain at an earlier forecast origin so
  that adapted Chronos-2 and LightGBM can enter the multiple-origin analysis without
  leakage.
- `src/experiments/run_zeroshot.py`: TTM runs on CPU when no GPU is present.
- `src/eval/stat_tests.py`, `src/viz/make_tables.py`, `src/viz/make_figures.py`,
  `src/eval/accuracy_vs_inventory.py`, `src/eval/bias_service_crossover.py`,
  `src/eval/inventory_sim.py` (`collect_predictions`): the `equ` variants are excluded
  from the main method set; `src/eval/family_robustness.py` maps TTM + EQ to the TTM family.
